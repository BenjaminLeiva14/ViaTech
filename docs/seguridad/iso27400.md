# Medidas relacionadas con ISO IEC 27400
No se afirma certificación ni auditoría de cumplimiento integral.
| Principio | Medida | Evidencia |
|---|---|---|
| Seguridad desde diseño | roles y esquemas definidos antes de conectar | firestore.rules |
| Mínimo privilegio | dispositivo independiente; consulta sin telemetría | pruebas de reglas |
| Protección de credenciales | Auth; sin almacenamiento manual de claves; backups desactivados | AuthRepository, manifest, gitignore |
| Transporte protegido | TLS del SDK nube; HTTP bloqueado en cloud | manifest y BuildConfig |
| Validación | tipos, enums, tamaño, rango, pertenencia y timestamps | validadores de reglas y simulador |
| Registro | auditoría atómica de administración, registros inmutables | repositorio y reglas |
| Continuidad | cola local con ID estable y confirmación, heartbeat | simulator.mjs |
| Ciclo de vida | dependencias fijadas, revisión de alertas | lockfile e informe de dependencias |
| Respuesta | desactivación, revocación, rotación, revisión | provisionamiento.md |

El laboratorio Emulator usa HTTP en loopback y cuentas ficticias: no prueba cifrado TLS. Wi-Fi WPA2/WPA3 es una condición del despliegue físico y no ha sido medido desde esta implementación. ISO es una guía, no una certificación automática por utilizar Firebase.
Riesgos pendientes: límites de tasa y abuso, App Check en nube, auditoría de inicios de sesión, retención/backups, verificación de TLS en hardware, almacenamiento seguro de credenciales ESP32, actualizaciones firmadas de firmware, calibración física. Las reglas son un prototipo y requieren revisión antes de distribución amplia.
